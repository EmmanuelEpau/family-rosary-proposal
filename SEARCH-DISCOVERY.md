## Answer engine approach

Google's current guidance: https://developers.google.com/search/docs/appearance/ai-features . No special AI schema, AI text file or separate optimization is required for AI Overviews/AI Mode. Important answers must be available in text, discoverable through crawlable links, useful and reliable. Indexed/snippet-eligible pages may qualify; inclusion is not guaranteed.

Keep answer paragraphs self-contained, specific and close to descriptive question/topic headings. Preserve sources and real authors/reviewers where supplied; never invent clergy approval, bylines or review dates. Native details keep complete text in the initial HTML. The guide already includes complete prayer words and sourced beginner answers. This revision clarifies the headings and adds direct opening links to prayers, mysteries and questions. All changes remain native editor blocks.

Every catalog item now has a stable /programs/{id}/ page containing substantive initial HTML, a unique title and description, source credits and related programs. Shelf cards still start playback directly; details links expose the same episode context. These review pages remain noindex. Native WordPress patterns, a dedicated program template and an explicitly invoked seeding helper accompany the static pages. Reviewed transcripts/captions and missing edition-specific dates/runtimes still need primary source evidence. Production canonical ownership and indexability remain launch decisions. Add VideoObject only when verified metadata and visible watch content agree. Do not infer first-party viewership from YouTube counts or mark recordings as live events.

## Technical and release requirements

Current static proposal: eight main routes and 57 program pages with distinct titles and descriptions, language and viewport, oneH1 per page, textual prayers and listings, crawlable anchors and responsive layouts. Review pages deliberately retain noindex,nofollow; robots.txt allows fetching so robots metadata can be read. Do not remove review protection or submit this GitHub proposal to search engines. Production canonical URLs, sitemap and indexability belong to the approved ministry domain and final CMS/SEO configuration; this release does not certify them.

Before production: one owner for titles/descriptions/canonicals/schema to avoid duplicate output from an SEO plugin and theme. Confirm self-canonicals on final URLs, XML sitemap, existing hreflang/language destinations, redirects, robots directives and server responses. Use structured data only for supported visible facts; do not promise FAQ/HowTo rich results. Retain image dimensions/lazy loading and verify real mobile Core Web Vitals separately. Browser no-overflow checks do not certify field performance.
